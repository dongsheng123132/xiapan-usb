## 项目名称

虾盘：PicoClaw 随身 AI 维护盘

## 一句话介绍

把普通 U 盘与电脑整合成随身 AI 维护工具：PicoClaw 理解用户的问题，调用本机诊断和现成维护工具；设备钱包、技能、离线资源和维护记录随盘携带，减少重复配置与人工排查。

## 产品形态与阶段

选择最接近“现有设备整合”的选项；当前为可运行、可验证的早期原型。已经在实体 exFAT U 盘上验证 Windows 运行、真实云端工具调用与报告保存。macOS/Linux 完整原生运行、同盘跨电脑接续和从 U 盘开机救援仍在开发与验收计划中。

## 使用者、场景与问题

面向个人用户、为家人维护电脑的技术用户，以及小型团队的现场维护人员。电脑变慢、网络异常或需要配置 AI 工具时，人们往往要重新查资料、下载软件、辨认系统与设备，再逐项执行。网络中断又会阻断在线问答和资源下载。

虾盘把 Agent、可用工具、维护步骤和事先准备的资源放在同一块盘里。用户在当前电脑启动后，用自然语言提出问题；本地诊断可以直接使用，云端分析使用随盘钱包，本地小模型作为备选。当前已验证体检、网络设备识别、维护工具入口和报告保存，通用软件安装和驱动自动修复仍属后续工作。

## Agent 实际做什么

Agent 根据用户问题选择受控动作，读取当前电脑的系统、内存、磁盘、进程、网络设备或本盘资源。它收到真实工具结果后解释发现并提出下一步。需要保存报告或打开维护工具时，页面展示待确认操作；用户确认后，执行结果回到同一对话，记录保存在 U 盘。

已实测的核心流程是：用户提出内存与磁盘体检需求，原生 PicoClaw 通过虾盘云调用本机体检，依据结果回答，再申请保存报告；用户在页面确认后，本盘实际生成一份报告。它没有执行未经验证的清理、驱动安装或系统重装。

## 硬件整合与差异

原型使用普通 U 盘作为可携带的运行、资源与状态介质，使用当前电脑的处理器、内存、网络接口和系统维护工具。启动后重新读取当前电脑状态，Agent 经共用动作核心访问本机能力，而对话、报告和设备钱包留在盘中。

我们的工作重点是低门槛的便携交互、免账号钱包接入、维护流程与工具协作。PicoClaw 作为现有开源 Agent 引擎复用，传统救援和维护工具按许可证与平台要求逐个接入。跨电脑接续会作为下一阶段的重要实机验证，当前不把它写成已完成能力。

## 系统如何工作

Windows 版以一个约 8.1 MB 的 Go 程序启动本机浏览器界面。PicoClaw v0.3.1 在 U 盘内运行，使用虾盘云设备钱包；经临时本机 MCP 接口调用与 GUI/CLI 共用的动作核心。网络设备检测读取真实硬件 ID、驱动版本和故障码。写入和打开工具经过可见确认，记录原子写入本盘。

可选离线包包含 llama.cpp CPU 运行时与 Qwen3.5-0.8B 量化模型；已验证在这台 Windows 电脑的启动、问答和停止，尚未验证物理断网及低配置旧电脑性能。轻量评审包仅含 Windows 核心与 PicoClaw，不包含模型权重或预充值凭证。

## 深圳阶段目标

1. 在第二台真实电脑验证同盘启动、重新识别设备、接续任务和钱包状态。
2. 完成一个网络维护闭环：识别硬件、匹配有来源与校验值的离线驱动、明确确认、执行后复查。
3. 优化自然语言维护、工具集合和断网入口之间的衔接，并验证 macOS/Linux 的原生 Agent 资源与运行路径。

## 开源与支持需求

自有核心源码采用 MIT 许可证，计划公开动作接口、维护 skills、构建与验收脚本；保留 PicoClaw 及其他上游许可证。钱包服务可独立接入，用户凭证与私人运行记录不进入公开源码或分发包。

希望获得设备整合、AI 产品体验、现场演示与跨平台工程方面的支持。

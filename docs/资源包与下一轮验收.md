# 资源包与下一轮验收

资源扫描与可执行安装是两层能力。用户把文件放进盘里，程序可以显示它；只有注册过安装适配并通过验证的包才可一键执行。当前安装适配只有 portable-check。

后续资源包应带 package ID、版本、官方来源、许可证、系统/架构、SHA-256、所需空间、安装动作与成功判据。实际安装应由维护核心实现，聊天、GUI 和终端只调用同一个动作。

| 下一轮模块 | 验收判据 |
| --- | --- |
| 有额度的虾盘云 Agent | 从真盘提出真实问题，模型调用本机检测，依据结果回答；安装/报告经确认后执行，正确展示失败与结果 |
| 同盘换电脑 | 在第二台物理电脑从同一块盘启动，重新识别系统，读取既有对话/报告；钱包保留，不沿用上一台的绝对路径与硬件状态 |
| Node / Codex / Claude Code / U-King 等 | 按平台探测已安装版本，优先使用已验证本盘包，展示目标与影响，实际启动检查版本/登录或服务状态；没有包时给出正确下载入口 |
| 驱动与网络维护 | 先收集设备与错误证据，驱动精确匹配硬件 ID/平台；网络修复说明修改项，保存可回滚的原配置，再检查目标是否恢复 |
| Ventoy 与救援镜像 | 独立制作测试介质，在物理电脑的 UEFI/BIOS 实际启动，并验证镜像中的工具；钱包和模型挂载行为另验 |
| 备份 / 克隆 / 恢复 | 辨认源和目标，先在专用测试盘验证输出与回滚；恢复到健康介质，检查文件或镜像内容 |
| 老电脑与完全断网 | 给出具体 CPU/内存、模型与量化、首次启动/回答时间、失败结果；提前准备资源，在物理断网后完成真实任务 |

比赛展示先选一个能完整完成的维护场景。录制实体 U 盘启动、用户提出问题、真实检测、确认与输出，成片不超过一分钟。未跑通的系统重装、跨电脑或云端 AI 能力不能当成已经完成的演示。

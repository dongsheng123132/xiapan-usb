# U-PicoClaw 便携发行验证

应用版本：0.5.4-portable-preview。PicoClaw：v0.3.1 / u-pico.1。2026-10-14。

## 源码与交付链路

本次分支保留随身AI盘定位。远端main已转向公司IT排障产品，移除了钱包和便携工具；本分支不覆盖该产品线。自建界面、钱包、固定Pico、传统工具来自同一源码仓；发盘目录由 scripts/package-portable.py 生成。

构建清单记录提交、Go版本、三平台应用哈希与源码指纹；打包要求干净工作树并核对原始源码、交付源码快照与构建指纹相同。固定Pico core/launcher分别校验，打包完成后才从.building目录改名。发货data为空。

## 可重复的验收

- `go test ./...`：钱包并发、轮换恢复、设置迁移、缓存多进程/损坏修复/降级、文件路径边界、资源哈希、离线维护和原生配置保留。0.5.2 增加 Mac 固定工具路径/平台/确认边界，以及自带 API 路径、鉴权、token 参数和仅测试不保存的协议验证。
- `go vet ./...`：静态检查。
- 设置 `XIAPAN_PICO_INTEGRATION=1` 后运行 `go test -run TestPinnedGatewayIntegration -count=1 -v`：真实固定Pico进程对接本地假模型，不花额度；验证连续会话进程复用、原生文件工具、凭证替换、官方面板认证和会话、官方Restart后两套界面继续共用服务、更新入口禁用与进程清理。
- `scripts/build.ps1`：Windows x64、Mac ARM64、Mac Intel、Linux x64 主程序交叉构建。成品包仅含前三平台的Pico运行时。
- `python scripts/verify-portable.py <母盘> --output <证据.json>`：核对每个发行文件、空白data、实际母盘程序的HTTP启动、离线向导、无自动开户、按需Gateway和退出。该脚本的启动时间只计进程创建到HTTP首页，不计浏览器绘制、Gateway或模型响应。

前端用隔离DOM/VM验证：启动后台请求挂起仍可操作；不自动创建钱包；应急诊断直接调用本地动作；原对话保留；官方入口仅打开一次；缓存状态与中英文显示。此项不是浏览器截图审查。

另用现有 Playwright/Chromium 运行真实 Windows 构建：验证首页输入、按需启动请求、应急/缓存/模型设置/工具目录，浏览器错误为零；检查桌面与 390px 窄屏，无水平溢出。钱包面板仅用拦截占位验证，未向后端开户或充值。报告和7张截图保存在制作工作区 `evidence/portable-ui-browser/`。

0.5.2 在真实 Chromium 中通过 10 组双语行为检查：英文启动和自然语言示例、按英文用途搜索、工具文字覆盖、中文切换、切语言保留 API 表单、保存与测试分离、Gemini 提示、Mac 5 个入口与搜索、中文动作协议保持。浏览器测试使用本地假接口，没有外部模型或钱包调用；它验证界面绑定与展示，不替代真实服务验收。

## Mac Apple Silicon 与实体盘验收（2026-10-14）

在 macOS 15.6.1 / arm64、62.9GB 实体 USB / ExFAT 上，用 0.5.2 母盘的哈希校验资源与空白专用目录验收。盘内路径包含中文及空格。原发行主程序的首页、脚本资源、离线向导、按需 Gateway、无自动开户、显式退出和端口清理通过；5 个 Mac 系统工具路径均可用，活动监视器实际启动并关闭了本次创建的进程。

原启动器的首次程序缓存复制到 HTTP 首页完整返回为 537.33ms，随后缓存命中为 46.74ms / 47.00ms。测试把程序缓存指向临时目录；OS 文件缓存未清空，且计时不含浏览器绘制、Gateway 或模型响应。这不是所有 U 盘的冷启动性能承诺，也不是 Finder 首次信任验收。

真实固定 PicoClaw 接本机假模型后，原 0.5.2 在更新测试凭证时失败；APFS 临时目录与 ExFAT 都复现。最小 Mac 探针确认 `Wait4` 返回 `0x117f`、进程状态为停止，但 Go BSD 的 `WaitStatus.Stopped()` 返回 false，清理因此漏掉旧进程。0.5.3 按本次不请求 continued 事件的 `Wait4` 停止标记判断，继续只结束本次拥有且已确认停止的进程组。

修复候选在 APFS 与盘内临时目录均通过 `TestPicoProcessControlKillsStoppedLeader` 和完整 `TestPinnedGatewayIntegration`；后者分别为 6.15s / 9.43s。覆盖真实文件工具写入、共享会话与 Gateway、两套界面的凭证更新、官方认证、两次原生 Restart 接续、禁用更新和所有权进程退出。测试没有真实模型、钱包开户或充值请求。摘要证据见 [Mac 实机记录](evidence/macmini-20261014.json)。

最终 0.5.3 母盘由干净源码提交 `d725360` 构建、打包，Windows 完整母盘哈希与行为验收通过。随后把该母盘的 Mac ARM 主程序、原启动器和固定运行时复制到同一实体盘的新中文空格目录，核对哈希后重新通过首页、工具、原生文件写入、测试凭证轮换、共享历史和显式退出验收；测试进程无残留，生成的数据归档到验收目录，试用 data 恢复为空。此轮首次程序缓存复制到 HTTP 首页为 276.53ms，缓存命中为 52.72ms / 39.57ms，计时边界同上。见 [0.5.3 实际发行程序记录](evidence/macmini-release-0.5.3-20261014.json)。Mac 盘上是 ARM 验收子集，未复制 Windows 工具和 Intel 运行时。

## 已知交付边界

0.5.4 按宿主系统适配首页示例、维护入口、网络结果、启动救援和快捷键；共用动作核心过滤不适用的便携软件和选装资源。Mac 网络检查显示接口与地址，并给出 macOS 说明；未读取的可用内存显示未获得。制盘配方生成中英文 Mac 校验入口，中英快速入门同步更新。三种平台的真实 Chromium 夹具检查均通过，见 [平台界面记录](evidence/platform-ui-0.5.4-20261014.json)；该记录验证界面绑定，不替代 Mac 后端实盘验收。

0.5.4 最终母盘由干净提交 `ae2fe21` 生成，1,619 个固定文件、空白 data 与 Windows 发行程序行为检查通过，见 [完整母盘记录](evidence/master-0.5.4-20261014.json)。该母盘 Mac ARM 产物在实体 ExFAT 盘通过中文空格路径、实际网络接口/系统/进程读取、排除 Windows 工具资源、五个系统入口、活动监视器启动、原生文件写入、测试凭证重启、历史保留及退出清理。无测试进程残留，生成的数据归档后试用 data 为空；见 [Mac 0.5.4 实盘记录](evidence/macmini-release-0.5.4-20261014.json)。

首次实盘校验发现 Windows 生成的 CRLF 清单会被 macOS shasum 当作带回车的文件名。配方改为生成 LF 清单，Mac 校验入口先在临时文件中规范化换行，再执行校验。真实脚本分别通过 LF、CRLF 与个人 data 排除检查，并对缺失或损坏的固定文件返回失败；未修改用户文件或关闭系统安全功能。

- Windows维护入口为9款便携工具+9项系统工具。驱动仅提供硬件信息、库存和已准备的3DP Net 21.01旧库，不声称自动匹配、安装、回滚或适配所有Windows 11网卡。
- Mac ARM 已在上述 Apple Silicon 实机和 ExFAT 实体盘完成分层验收；Mac Intel 仍仅构建，首次 Finder 信任/系统授权及五个工具的完整交互仍待验收。实际打开的是活动监视器，其余四项验证系统应用路径可用。
- 自带 API 的连通性验收使用本地假服务，没有客户的 Kimi、智谱或 Gemini 真实 Key；不能宣称已完成各家模型实测。Gemini 的复杂工具任务推荐原生 provider，兼容模式不保证全部多轮行为。
- 宿主程序缓存只保存公开二进制，首次需读U盘；Key、钱包和工作状态直接留盘。第三方维护工具目录未整体搬到宿主，避免ini/个人设置遗留电脑。
- 充值地址只读检查可达；模型目录无凭证返回401符合鉴权预期。未做真实充值或调用收费模型；生产钱包余额不能用假模型测试替代验证。
- 0.3秒是待实机证明的指标。开发机C盘为NVMe，不能把其HTTP启动成绩宣传为所有U盘冷启动成绩。实际制盘验收JSON保留在制作工作区的evidence/，不会把测试凭证带入成品。
- 本包不是WinPE引导盘。系统无法启动时需另备已经验证的恢复环境。

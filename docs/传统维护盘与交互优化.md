# 虾盘 AI 多功能维护盘：功能继承与交互决定

2026-10-02。依据用户本轮决定，产品采用独立轻量工程。本工作区为新产品源码；已有 U-King 的成熟能力以后通过稳定动作适配复用，不复制另一套公共业务逻辑。9 月 30 日同仓建议保留为历史方案，不再作为本轮新工程的组织决定。

## 传统维护盘提供什么

参考 Hiren’s BootCD PE、SystemRescue 和 Ventoy 的官方功能列表。它们分别提供 Windows 救援工具集合、Linux 救援环境和多镜像启动底座。功能继承按场景和工具接口开展；不将整个第三方软件集合重新复制分发。

| 传统能力 | 虾盘中的体验 | 本轮状态 |
| --- | --- | --- |
| 硬件、内存、磁盘诊断 | 「给电脑做个体检」，先解释证据，再建议工具 | 已有真实系统/内存/磁盘检测；SMART、温度、内存压力测试待接入 |
| 网络与驱动维护 | 「解决网络问题」，区分网卡、DNS、代理与服务故障 | 已有只读网卡检查；实际网络修复和驱动安装待接入 |
| 软件与环境安装 | 检测平台、查看资源、展示计划、安装、验证 | 已有内置便携体检工具的真实安装与启动验证；其他软件为后续资源包 |
| 备份、镜像与克隆 | 先辨认源盘和目标盘，再给备份方案 | 已有通用 skill；镜像/克隆动作待接入 |
| 数据恢复 | 先保护源盘，恢复到健康介质，实际检查输出文件 | 已有通用 skill 与方案；实际恢复工具待接入 |
| 分区、启动修复、系统安装 | 单独的救援流程，明确目标设备与影响 | 已有方案与 skill；没有抹盘或写引导功能 |
| 多镜像启动 | 通过 Ventoy 和匹配镜像制作启动盘 | 后续独立模块；本轮试用目录不是启动盘 |
| 本地 AI | 提前带好引擎与模型，按电脑能力运行 | 已实现已校验资源的启动、本地对话、停止；验证结果看本轮测试记录 |

## 界面原则与已落地交互

1. 首页按「体检、安装、网络、离线 AI、文件、系统救援」组织，用户先选问题。
2. 描述问题后先给方案，检测与安装由同一动作核心执行。模型只提供解释和建议，不能输出一条命令就直接执行。
3. 无模型时提供明确标注的维护向导；资源备齐时首页可选本盘离线 AI，首次提问会校验并启动，无须用户手配端口。
4. 检测完成显示来自本机的结果，不用虚构健康分数。高级细节折叠，日常操作保持简短。
5. 安装位置说清楚。当前真实安装到本盘新目录，保留原文件；完成后显示启动验证结果。
6. 报告随盘保存。换电脑后重新检测，并保留旧报告的来源，不拿旧电脑的数据冒充当前电脑。
7. 所有样式、字体回退和界面脚本本地提供，无 CDN、在线字体或外部前端依赖。
8. 程序只监听本机回环地址；本地模型仅绑定本机。退出按钮结束本次模型与维护服务。

## 本地模型边界

本轮准备的测试资源为 Qwen3.5-0.8B Q4_0（563,036,064 字节）和 llama.cpp b11146 Windows CPU 运行时。文件来自官方项目，固定来源与 SHA-256 已写入构建清单，清单嵌入程序。

模型很小，可以用来验证离线部署与中文维护问答，不作为复杂系统修复的独立决策依据。执行由可校验动作承担。后续按目标机实测选择更强的可选模型，不能用 64GB 开发机的结果推断所有老电脑。

“断网后安装本地模型”必须是从已准备的本地资源安装，或从另一健康介质取得资源。完全没有权重和引擎时，只能使用确定性工具和维护向导。

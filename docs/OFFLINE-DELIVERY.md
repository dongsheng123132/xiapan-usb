# 离线维护盘交付

此分支基于 `5e20bea`，保留 PicoClaw、离线模型、便携工具和网络诊断，独立于已精简的公司网管版本。

发盘目录必须由 `scripts/package-offline.py` 从源码及已校验的资源生成，不能复制用过的发行目录。客户使用后产生的 `data/` 不得回灌母盘。

本地模型为通用 Qwen3.5-2B Q4_K_M，配合维护知识使用，未进行电脑维修专项微调。主维护入口无需账户、API Key 或互联网；可选 U-DSH 的设备钱包及云服务另需联网。工具适用范围为可以进入 Windows 的 x64 电脑；复制目录不会生成 BIOS/UEFI 启动盘。

## 生成与验收

构建环境需 Go、Python 3.11 或更高版本、Git。`resources` 指已有可信模型、llama.cpp、PicoClaw 和六款便携工具的资源根目录；打包器逐项校验固定 SHA-256。新增硬盘工具由 `scripts/prepare-customer-extras.py` 生成，包含对应许可证、源码和依赖源码。

```powershell
python scripts/package-offline.py --resources '资源根目录' --extras '工具准备目录/ready' --output '全新输出目录'
python scripts/verify-offline-package.py --master '全新输出目录' --qa-smoke
# 在真实 U 盘的新目录中验证副本；不会把测试数据写回母盘。
python scripts/verify-offline-package.py --master '全新输出目录' --test-parent 'G:\虾盘验收' --qa-smoke
```

可选大龙虾必须明确传入 `--large-agent '已独立验收的发行包' --large-agent-sha256 '该发行包的SHA256'`。本版采用 U-DSH 0.2.2 独立源码构建，旧 0.2.0 首发自解压包缺少必需文件，已弃用。没有客户凭据与运行依赖齐全是两项不同的检查，归档测试通过也不能代替程序启动验证。

启动救援准备材料通过 `--boot-assets '已审查的救援材料目录'` 加入；该目录须有 `SHA256SUMS.txt`，打包器验证文件清单后复制到 `04-启动救援准备`。准备材料不等于制作启动盘，镜像只有下载完整且校验后才可列入已附带内容。

客户母盘不允许 `--allow-dirty`；该参数仅用于内部候选。打包器从当前源码构建、检查离线模式与内置工具目录，写入源码快照、提交号、资源清单及校验脚本，不读取开发机的账号配置。

验收脚本仅运行临时副本：隔离用户目录、移除继承的提供商凭据、代理设为不可用地址但允许 localhost，校验模型加载、实际推理、工具就绪状态、中文空格目录迁移、进程退出及母盘未被污染。它没有禁用本机网卡，不能替代真正断网或另一台客户电脑测试，也不能阻止忽略代理变量的程序联网。固定指引及实际模型问答的内容须人工审读，功能通过不等于模型事实准确。

真实 G: exFAT U 盘测试证据为 `evidence/verify-offline-20261012T073749Z-z74tsrek.json`：本机加载模型 4.766 秒，回答 12.953 秒，生成 74 tokens；迁移到中文带空格目录后，只读体检与随盘模型识别成功，模型端口关闭，主服务退出，母盘 `data/` 为空且清单未变。测试仍在同一台 Windows 11 x64 开发机上完成，没有拔网或使用第二台机器。该证据覆盖当时的主维护程序和模型，不能代替新版 U-DSH 或新增救援材料的独立验收。

实际测试发现 2B 模型会编造故障原因，不能按维修专家交付。离线客户模式将磁盘异响、文件误删、组织设置错误及有线断网等已识别场景先交给 `catalog/offline-references.json` 的固定知识指引，回答明确标记“未调用模型”，并且不先扫描电脑。其余问题仍由本地模型回答，仅作参考。这是常见场景分流，不能保证识别所有描述或消除所有模型错误。`--qa-smoke` 分开验证三条固定指引及一条真实模型术语问答，并核对各轮实际生成次数，不能用固定答案冒充模型验收。

客户双击 `开始维护.cmd`。对话、报告和工具配置会写入客户副本，母盘 `data/` 应一直为空。交付目录内的 `校验母盘.ps1` 同时检测文件缺失、变化及额外文件；校验母盘时不要把自己的文件混放在里面。

## 本版内容边界

- 默认离线链路是 Qwen3.5-2B + llama.cpp CPU + 维护知识。PicoClaw 0.3.1 已附带，但未声称它已与小模型完成离线工具调用联调。
- 六款原有工具加 CrystalDiskInfo、PhotoRec 文字界面、TestDisk，共九个便携工具入口；另有九个 Windows 系统工具入口，包含网络适配器和网络设置。PhotoRec/TestDisk 共用同一个 CLI 目录，不包含 Qt 图形版本；系统入口依赖客户 Windows 自带组件。
- 可用 `--network-assets` 加入带严格 SHA256 清单的旧网卡离线材料，生成 `05-旧网卡离线驱动-可选`；本次为 3DP Net 21.01 官方完整驱动池，未对客户硬件安装测试，不宣称覆盖现代全部网卡。`drivers/` 留给已匹配的客户型号专用驱动。流程为：读取硬件 ID，并记录电脑型号、Windows 版本及架构；在有网电脑从电脑或网卡厂商官网下载匹配驱动，核对来源、签名或厂商校验值；复制到 `drivers/`，再由维护人员确认后手动安装。不声称能自动匹配或离线下载驱动。
- U-DSH 0.2.2 采用 Electron 桌面窗口承载 Harness WebUI，需解压至本机 NTFS 新目录。离线启动已通过，但尚未完成与本盘小模型的整机联调；离线启动成功不证明模型问答或云服务可以离线使用。
- U-DSH 设备钱包、“一键开通并充值”为联网云功能。0.2.2 候选（`ac7c807…`）已在隔离副本、本地钱包模拟服务及不可达端点下验证手动钱包入口、开通、配置保存、充值页链接、只绑定一次及断网时界面启动；未创建真实钱包或付款。证据为工作区根目录 `.cache/udsh-customer-tests/run-iId2tB/result.json`。修复新钱包零余额时自动打开钱包的提交为 `168e19ba0170e8c58951783e43e551da55043c0e`，75 项测试通过；最终 SFX 149,305,126 字节，SHA256 `3db16af42f8c29f03570deafd9808496a4a1dd08e266d36b093ec2b91fd074bf`；实际重新解压后的零余额首启自动弹窗、一键充值 URL、真实配置落地、绑定不重复及模拟断网启动均通过。两个主进程正常退出，证据 `.cache/udsh-customer-tests/run-PvW5GC/result.json`（工作区根目录）。这些联网功能不是主维护入口的离线依赖。
- `04-启动救援准备` 提供 Ventoy 及对应源码、许可证等材料，不代表 U 盘已经安装引导或完成救援环境试启动。完整 SystemRescue ISO 未附带，下载断点只留研发缓存；WinPE、Windows 安装镜像仍未附带。制作启动盘需单独确认目标设备、备份并验收，不能由复制目录替代。
- [维护场景覆盖表](offline-customer/维护场景覆盖表.md) 区分检查、工具、指引与缺失环境，覆盖断网、驱动、磁盘、启动、系统及外设等常见场景，不能宣传全部自动修复。只读场景审计证据在 `.cache/offline-scenario-audit/evidence/`，包括七项实际动作、四种固定指引及十二项针对性测试。
- 实际验收结果保存在 `docs/offline-customer/验收记录.txt`；模型和 G: U 盘测试的 JSON 证据在开发工作树 `evidence/`，临时测试副本在各次记录的 `test_directory`。不会将测试对话带入客户母盘。

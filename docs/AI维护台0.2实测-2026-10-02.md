# AI 维护台 0.2 实测记录

2026-10-02。本轮根据用户反馈改为云端优先的持续对话维护台，保留本地模型为备选。源码沿用本工作区独立工程，不修改已有 U-King 工作树或把未合并 PR 当作已发行能力。

## 界面和交互

原来的一问一弹窗改为任务对话：问题、实际动作结果、待确认安装、报告和后续回答留在同一段记录中。专业模式展示真实 JSON 与动作日志；Ctrl K 快捷菜单和 Windows 终端菜单供熟悉工具的用户直接选动作。

真实界面测试发现长对话中输入框会遮住确认按钮，已改为对话独立滚动、输入区域正常占位。修复后验证安装按钮处于最上层且可点击，安装完成卡片、报告完成卡片均实际出现，浏览器未记录脚本错误。1440×1000 和 900×700 检查可见布局；900 宽专业侧栏会压缩主区，可关闭专业模式增大工作区。

## 云端与钱包

实际连到虾盘云，新建本盘免注册钱包；只读余额接口返回 1 个校验额度。服务端模型列表真实读取，界面默认 deepseek-v4-flash；结合服务端计费类型筛选模型，不维护一份手写名称清单。接口目录出现不代表每个模型都有受控工具能力。

充值页只读检查 HTTP 200，界面一键充值实际打开系统浏览器，未付款、未管理员充值、未调整钱包余额。凭证没有进入截图、模型提示、源码或本轮公开记录。

用新钱包发起真实云端文本请求，服务端拒绝。界面保留问题并提示检查额度或切换本地工具，没有生成假回答。因此有额度的真实云端 AI 诊断及工具调用尚未验收。

Go 核心的本地 HTTP 回放另外验证了：模型读取真实系统结果，再申请 report.create；没有用户确认时不写报告，确认后恰好写一份，陈旧重复确认被拒绝。钱包测试包含同根并发一次绑定、轮换提交失败后不重复 mint、未知 pending 保留、余额失败显示未知、损坏钱包文件保留并允许验证后导入。

## 平台与救援边界

Windows x64、macOS ARM64/x64、Linux x64 可构建。Linux x64 核心在 WSL Ubuntu 实际完成 system.inspect、report.create、reports.list，使用独立 /tmp 目录；WSL 报过既有 Windows PATH 中 E:\U-ClawX 项无法转换，但这些动作成功。没有修改该 PATH 或用户环境。

Mac mini 的 SSH 连接超时，没有更改网络或远端机器。因此 Mac 实机、Linux U 盘挂载、同盘换另一台物理电脑接续仍待验收。

当前盘是系统内的便携维护工具。没有添加引导分区或实拍启动 Ventoy、WinPE、SystemRescue；启动救援界面清楚显示此边界。通用软件、驱动、克隆/恢复/系统安装没有伪装成已完成动作。

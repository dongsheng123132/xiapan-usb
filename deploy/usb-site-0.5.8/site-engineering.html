到了 10 月，我为什么还在把 AI 装进 U 盘？

设备钱包 · 真实 I/O · 本机缓存 · 跨系统便携

AI 工具已经很多了。但我到朋友家帮忙看电脑时，还是会碰到一个很具体的问题：他的电脑，没有我熟悉的 AI。

临时装软件、找配置、填 API Key，往往比开始排查还麻烦。换到一台陌生电脑，我自己的记忆、Skills 和工作记录也不在那里。

所以我继续做虾盘：把 AI 装进 U 盘，随身带着走。插上，主动打开程序，就能开始干活。 在支持的系统上免安装；使用虾盘云，免手动填写 API Key。

今年 2 月，我开始做 U-Claw。到现在，项目约有 1,800 个 GitHub Stars；按我汇总的情况，全网基于我的开源代码销售的 U 盘合计约 60 万个。后一个数字是全网合计，不是我个人的销量，也不是新 Lite 版的销量。

这次准备 Spotlight，我想讲讲这块盘背后的工程。盘很小，事情却不少。

选盘和硬件测试现场

我在测试不同的 U 盘和硬件方案。照片里的样品，不代表每一种都是最终交付配置。

/ / /

1. 设备钱包：把填 Key，变成打开钱包

新手通常得先注册模型平台，再申请、复制、填写 API Key。我希望把这段流程缩短成：打开随盘钱包，一键进入充值，到账后开始使用。

我们设计了一套随盘设备钱包：云端记录钱包余额，服务端签发凭证，客户端带着凭证走。换电脑，不必每次重新填一遍 Key；凭证轮换与钱包余额也分开处理。

这里的“钱包”是 AI 用量钱包。它不等于带安全芯片的硬件钱包，默认云 AI 仍然需要联网，模型额度另行计费。熟悉 API 的人，也可以接自己的服务。

我把它当作自己的产品创新来讲：让便携 AI 的使用门槛更低。现有证据不足以证明“全球首创”，因此不把这个词写成宣传承诺。

/ / /

2. 硬件 I/O：先测清楚，再选盘

做随身 AI，不能只看包装上写着 USB 3.0，或者顺序读取多少 MB/s。程序启动、加载依赖、浏览器写缓存，经常涉及很多小文件，随机 I/O 同样重要。

为此，我做了开源工具 UBench。它通过 Windows 的无缓冲 I/O、macOS 的 F_NOCACHE 等方式减少操作系统缓存对结果的干扰，并提供顺序读写、4K 随机读写、持续写入与容量检查等测试能力。

这让我能用实际负载比较不同盘和硬件方案，而不是只按标称参数选盘。UBench 的完整测试配置与实现公开在 GitHub，别人可以检查、复测。

仓库 README 中的跑分示例用于解释测量方法；它们不是所有虾盘的出厂性能，更不能直接当作硬件优化前后的提升比例。最终成品要按实际型号、主机与测试条件报告成绩。

/ / /

3. 缓存：工作随盘，重 I/O 留在电脑

把所有读写都压在 U 盘上，便携是便携了，启动和使用体验却可能很差。我们的做法，是分清哪些东西必须随人走，哪些可以在本机重建。

Lite 首次需要时，将经过校验的公开程序文件准备到本机缓存，之后复用。配置、钱包凭证、会话和盘内工作文件仍留在 U 盘。它不代表所有第三方工具的缓存都已经迁移。

Pro · U-Claw 还处理了 Node 编译缓存和受管浏览器目录，把这些高频 I/O 放到电脑本地。OpenClaw 的配置、记忆、会话、设备身份与授权状态仍随盘。

浏览器目录里可能有登录状态，因此新电脑的浏览器登录不会自动跟着走，本机也可能留下缓存和浏览器数据。我们承诺的是已保存工作与盘内资料的便携接续，不是拔盘后电脑零痕迹，更不是把运行中的进程搬到另一台机器。

一组刚完成的真实 U 盘测试

2026 年 10 月 14 日，在 macOS 15.6.1、Apple Silicon 和一块约 62.9 GB 的 exFAT 实体 U 盘上，Lite 原始 0.5.2 版本记录了以下启动序列：

测量轮次到首页 HTTP 响应完成
首次程序缓存准备537.33 ms
后续缓存命中，第二次46.74 ms
后续缓存命中，第三次47.00 ms

计时包含从启动到首页 HTTP 响应完成，不包含浏览器显示、PicoClaw Gateway 就绪和模型回答。这里比较的是首次准备与后续复用，没有清空操作系统缓存，也不是新旧代码的同条件 A/B。所以我会说“这次实测，后续缓存命中约 47 ms”，不会说“所有电脑 47 ms 完整启动”。

官网原来的约 0.3 秒，来自旧 0.4.1 / 0.4.2 在 Windows 闪迪 U 盘上的本地服务测试，记录为 0.286 / 0.275 秒。产品、平台和计时边界都不同，不能与上表拼成优化前后对比。

少让 U 盘重复读写程序和缓存，能够减少盘上 I/O 压力。至于延长寿命多少年、写入量减少多少，目前没有同条件的写入量或耐久测试，我先不报数字。

4. exFAT：跨系统便携，要过实际运行这一关

exFAT 便于 Windows 和 Mac 读写同一块盘，但“文件能复制”并不等于复杂程序就能正常运行。文件身份、目录行为、进程退出和重启，都要逐项验证。

这次 Lite 的 Mac 测试先暴露了一个进程停止状态的识别问题。它在 APFS 和 exFAT 上都能复现，所以不能简单归因于 exFAT。0.5.3 候选版修正后，Apple Silicon 上的 APFS 与实体 exFAT U 盘集成测试均通过，覆盖原生文件写入、共享历史、凭证同步、原生重启和退出后的进程清理。

测试使用真实 PicoClaw 加本地模拟模型，没有产生付费模型调用。它不等于已经验收了所有 Mac 机型、所有权限弹窗或真实充值链路；Intel Mac 目前只完成构建。

Pro 的旧版本已有 Windows exFAT 运行记录。最新 OpenClaw 2026.10.2 则遇到了重命名后的文件身份校验问题，现在已有带实际盘探测、内容校验与锁的适配代码；我看到的最新记录仍在验证阶段。因此，现阶段不能笼统宣布“最新版 Pro 在 Windows 和 Mac 的 exFAT 上全部验证完成”。

我想让它成为一个随身工作搭子

Lite 用 PicoClaw，轻量上手；Pro 是 U-Claw，带走熟悉的 OpenClaw 工作环境。 网站的 29.9 MB 是 Windows 体验包的下载大小，不是包含多平台运行时和工具包的整盘体积。

它能在一台没有预装 AI 的兼容电脑上，帮你查看状态、读写文件、整理资料，再配合维护工具排查问题。断网时可以用本地诊断与已准备好的工具；默认云 AI 需要网络。它也不能代替无法启动的系统所需的引导救援盘。

办公室没做完，保存任务、退出程序、安全移除；回家换一台电脑，再打开，从已经保存的记录和盘内文件接着干。

AI 工具会继续变多，电脑仍然会出问题，人也仍然会换电脑。我想解决的，就是这些具体时刻里的一点麻烦。

来 Spotlight 展位，插上试一个任务。也欢迎看看源码，一起把这块小盘做得更好用。

# 电脑体检与维护分诊

把用户描述转换为可验证的维护任务。先判断当前能否进入系统；运行中的系统和救援环境要使用各自可用的工具。

优先调用动作列表发现能力。虾盘可执行 `action list --json`，然后用 `action run system.inspect --json --no-input` 读取系统、架构、内存与磁盘信息；其他宿主使用其等价只读检测接口。

只解释实际读到的证据。剩余空间、内存容量和网卡启用状态都不能单独证明故障根因。没有温度、SMART 或进程数据时，明确说明还缺哪一项，不编造健康分数。

按具体证据选择网络、安装、模型、数据救援或启动流程。清理与加速建议要能说明将影响什么；“一键优化”不能默认批量关闭服务、删除用户文件或改变安全设置。

交互采用「问题 → 检测发现 → 可选下一步 → 结果」。技术细节放在可展开区域；需要用户选择时给出与结果相关的少量选项。

当前虾盘预览可真实调用体检、资源扫描和报告动作，其他维护通过方案进入后续适配。可用 `report.create` 保存本盘报告；报告是检查记录，不标记为已经修复。

完成判据：用户能看到检测来源、未解决的问题、下一步，以及保存位置。换电脑后重新检测，不能继续使用上一台的盘符或硬件判断。
